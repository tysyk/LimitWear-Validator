# LimitWear Validator

Інтелектуальна система перевірки зображень для онлайн-платформи дизайнерського одягу.

Система аналізує зображення, які користувач може завантажувати на платформу дизайнерського одягу, та формує фінальний результат перевірки: `PASS`, `NEED_REVIEW` або `FAIL`.

## 🧱 Архітектура системи

Система побудована за pipeline-підходом. Вхідне зображення проходить послідовність етапів:

```text
image → quality gate → scene type → ROI / detectors → OCR / ML → rules → aggregate → explain
```

ML-модулі не приймають фінальне рішення самостійно. Вони формують сигнали, які передаються до rule-based шару. Після цього aggregate module формує фінальний статус перевірки.

Основні статуси системи:

| Статус | Опис |
|---|---|
| `PASS` | Зображення відповідає вимогам платформи |
| `NEED_REVIEW` | Потрібна додаткова ручна перевірка |
| `FAIL` | Зображення порушує правила платформи |

## ▶️ Як запустити проєкт з нуля

### 1. Клонування репозиторію

```bash
git clone https://github.com/tysyk/LimitWear-Validator.git
cd LimitWear-Validator/apps/validator-ml
```

---

### 2. Створення virtual environment

#### Windows PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\activate
```

#### Linux / macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
```

---

### 3. Встановлення залежностей

```bash
pip install -r requirements.txt
```

---

### 4. Запуск backend-сервісу

```bash
python -m uvicorn main:app --reload
```

Після запуску backend буде доступний за адресою:

```text
http://127.0.0.1:8000
```

Swagger-документація:

```text
http://127.0.0.1:8000/docs
```

---

### Аналіз зображення

**POST `/analyze`**

Формат запиту:

```text
multipart/form-data
```

Параметри:

| Поле | Тип | Опис |
|---|---|---|
| `image` | file | Зображення для перевірки |
| `profileId` | string | Необов’язковий параметр профілю перевірки |

```json
{
  "verdict": "NEED_REVIEW",
  "score": 75,
  "violations": [
    "KNOWN_BRAND_REVIEW"
  ],
  "explain": [
    "Image contains a potential brand-related element and requires manual review."
  ]
}
```

## 🖱️ Інструкція для користувача

1. Відкрити вебінтерфейс системи.
2. Завантажити зображення для перевірки.
3. Натиснути кнопку запуску аналізу.
4. Дочекатися завершення pipeline.
5. Переглянути фінальний статус:
   - `PASS` — зображення прийняте;
   - `NEED_REVIEW` — потрібна ручна перевірка;
   - `FAIL` — зображення відхилене.
6. Переглянути пояснення результату перевірки.

## 🧪 Проблеми і рішення

| Проблема | Можлива причина | Рішення |
|---|---|---|
| `ModuleNotFoundError` | Не активовано virtual environment або не встановлено залежності | Активувати `.venv` і виконати `pip install -r requirements.txt` |
| API не запускається | Помилка в залежностях або зайнятий порт | Перевірити встановлені пакети та порт `8000` |
| Docker не запускається | Docker Desktop не запущено | Запустити Docker Desktop і повторити команду |
| Зображення не аналізується | Некоректний формат або пошкоджений файл | Перевірити, чи файл є валідним PNG/JPEG/WebP |
| Довгий час аналізу | OCR або ML-модулі працюють на CPU | Зменшити розмір зображення або використовувати GPU |

## ⚠️ Обмеження системи

- Малі або стилізовані логотипи можуть бути складними для розпізнавання.
- OCR може помилятися на декоративних шрифтах.
- Якість результатів залежить від розміру та різноманітності dataset.
- Pretrained moderation model може давати хибні спрацювання на стилізованих ілюстраціях.
- Поточна реалізація є прототипом і потребує розширеного тестування перед промисловим використанням.
